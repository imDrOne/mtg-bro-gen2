# Эксплуатация

## Топология

- Один недорогой сервер (бюджет ≤ 5к ₽/мес суммарно, включая сам сервер).
- Docker + `docker compose`, без Kubernetes — оверхед k8s не оправдан на этом
  масштабе и бюджете.
- `docker-compose.prod.yml` (уже в репо как пустой tracked-скаффолд) —
  наполняется по мере появления сервисов, тем же списком, что
  `docker-compose.local.yml`, но с прод-значениями (реальные секреты через
  env, не дефолты).

## Домены

- Бесплатные поддомены DuckDNS.
- Reverse-proxy перед всеми REST/MCP-эндпоинтами с TLS (Let's Encrypt) —
  конкретный выбор (Caddy/Traefik/nginx) фиксируется отдельным ADR при первом
  реальном деплое (M1), сейчас важно только зарезервировать эту прослойку в
  топологии, чтобы сервисы не занимались TLS сами.

## Ресурсный бюджет

Ориентир на немощный сервер — почему инфраструктурные решения выше выбраны
именно так:

| Компонент | Почему так |
|---|---|
| Postgres + pgvector в одном инстансе | Один stateful-компонент вместо двух ([ADR-0005](adr/0005-pgvector-over-qdrant.md)) |
| Redpanda вместо полного Kafka | Совместимый протокол, кратно меньше RAM (нет JVM/ZooKeeper) |
| Redis | Лёгкий, только под cache-aside, без кластера |
| Метрики без сборщика (пока) | `/metrics` отдаём, но не поднимаем Prometheus/Grafana до M7 — экономим RAM, пока некому это дашбордить |
| distroless-образы для `cmd/migrate` | ~15 МБ на образ, минимальная attack surface у джобы с DDL-правами |

## Контракт CI-джоб (пайплайн — отдельная итерация)

Полный CI/CD пайплайн намеренно не проектируется в этом плане — фиксируем
только контракт, под который уже сейчас проектируется `cmd/migrate` и
Dockerfile-раскладка ([persistence.md](persistence.md#контракт-ci-джоб)):

```
build_migrations -> run_migrations -> build -> deploy
```

Каждый сервис — свой набор джоб (свой `Dockerfile`/`Dockerfile.migrate`,
собственный migrate-образ). `run_migrations` блокирует `deploy` — миграция не
прошла, деплоя не будет.

## Что осознанно не делаем сейчас

- k8s, service mesh — не тот масштаб.
- Managed-облачные версии Postgres/Kafka — бюджет не позволяет, да и цель —
  прокачать эксплуатацию руками.
- Blue-green/canary деплой — при одном сервере и текущем размере команды не
  оправдано; при экспансии на несколько нод — переоценить.
