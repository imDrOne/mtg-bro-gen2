# CLAUDE.md — deck

Гайд для Claude Code при работе внутри `services/deck`. Общесистемный контекст
— в [docs/arch/](../../docs/arch/README.md), корневые правила — в
[корневом CLAUDE.md](../../CLAUDE.md).

## Назначение и границы

Владеет двумя тесно связанными доменами в одной схеме БД, без искусственного
разделения ([ADR-0006](../../docs/arch/adr/0006-catalog-and-deck-in-one-service.md)):

- **Справочник карт** — зеркало Scryfall: карты, выпуски (sets), поиск.
- **Колоды и библиотеки** — сборка колод под любой формат с учётом бизнес-правил,
  личная библиотека карт пользователя (как на Moxfield), импорт/экспорт.

**Чем не владеет:** статистикой limited-форматов (`limited-stats`), статьями и
LLM-инсайтами (`article-parser`/`insight-provider`), идентификацией
пользователя (`authenticator` — `deck` только верифицирует токены через
`libs/authx`, не выдаёт их).

## Данные

- Схема БД: `deck` (единая для справочника и колод — см. ADR-0006).
- Роли: `deck_migrator` (DDL, только `cmd/migrate`), `deck_app` (DML, рантайм).
- Redis: cache-aside для карточных данных (`card:<id>`, TTL+jitter), защищён
  singleflight на промах — см. [patterns.md](../../docs/arch/patterns.md).
- Полные данные о картах храним только для тех карт, что реально нужны
  (то, что вернул Scryfall bulk `default_cards`) — не дублируем весь массив
  их метаданных сверх необходимого (изображения — по ссылке на Scryfall, не
  копируем).

## Внешние зависимости

- **Scryfall API** (`libs/scryfall`) — bulk-data эндпоинты для полного
  обновления справочника, поисковые эндпоинты для точечных запросов. Rate
  limit ~10 rps по их же рекомендации — соблюдается через `libs/httpx`
  token-bucket. При недоступности Scryfall — работаем на последнем
  импортированном снапшоте, не блокируем сборку колод.

## Контракты

- REST + OpenAPI (`api/openapi.yaml`) — наружу, для веб-фронта:
  - `GET /cards`, `GET /cards/{id}` — поиск и получение карт.
  - `POST /decks`, `GET /decks/{id}`, `PATCH /decks/{id}/cards` — сборка колод.
  - `POST /library/import`, `GET /library/export` — импорт/экспорт (форматы
    ниже).
- gRPC (`libs/proto`) — внутрь, для `mcp-gateway` и будущих потребителей:
  - `CardService.GetCard`, `CardService.BatchGetCards`, `CardService.SearchCards`.
  - `DeckService.CreateDeck`, `DeckService.SaveDeck`.
- Kafka out: `deck.saved` (через outbox, публикуется при сохранении колоды).

## Внутренняя раскладка (ориентир для M1–M2)

```
internal/
  catalog/      # импорт Scryfall, поиск, чтение карт
  deckbuilder/  # правила форматов, CRUD колод
  library/      # библиотека пользователя, импорт/экспорт
  importer/     # парсеры форматов: txt, csv, json, moxfield, tcgplayer
```

Пакеты общаются напрямую (не через gRPC внутри сервиса — это один процесс),
но через явные интерфейсы, не через прямой доступ к чужим внутренним
структурам — задел на случай будущего разделения по ADR-0006.

## Паттерны здесь

- **Singleflight** — дедупликация параллельных промахов кэша по одной карте.
- **Cache-aside + TTL/jitter** — карточные данные в Redis.
- **Token-bucket** — соблюдение лимита Scryfall.
- **Outbox** — атомарность «сохранить колоду + опубликовать `deck.saved`».

Полное обоснование — [patterns.md](../../docs/arch/patterns.md).

## Локальный запуск

```
task up                              # поднять postgres+redis+kafka
go run ./cmd/migrate up              # накатить схему deck
go run ./cmd/migrate seed --env=local
go run ./cmd/server
```

## Метрики и алерты

RED-метрики на REST/gRPC (см. [observability.md](../../docs/arch/observability.md)),
плюс `import_operations_total{source,status}` по каждому формату импорта.
Отдельных обязательных алертов для этого сервиса на старте нет (не фоновый
процесс) — только общий алерт на `readyz`-фейл и всплеск ошибок.

## Инварианты домена

- Правила легальности карт в колоде и лимит копий проверяются **всегда** на
  запись (`POST`/`PATCH`), не только на чтение/подсказке — не полагаемся на
  фронт в валидации.
- Формат-специфичные правила (например, синглтон в Commander, отсутствие
  лимита sideboard в Draft) — конфигурация, не хардкод одного правила на все
  форматы.
- Импорт никогда не приводит колоду в невалидное по правилам формата
  состояние — невалидные позиции репортятся пользователю, а не сохраняются
  молча.
