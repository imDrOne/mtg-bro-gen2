# CLAUDE.md — authenticator

Гайд для Claude Code при работе внутри `services/authenticator`.
Общесистемный контекст — в [docs/arch/](../../docs/arch/README.md), корневые
правила — в [корневом CLAUDE.md](../../CLAUDE.md).

> **Реализация ещё не выбрана.** [ADR-0008](../../docs/arch/adr/0008-oauth2-build-vs-buy.md)
> — статус Proposed, решается перед вехой M4 (Ory Hydra vs своя реализация на
> библиотеке, Keycloak исключён). Контракт наружу ниже не зависит от выбора и
> проектируется уже сейчас.

## Назначение и границы

OAuth2/OIDC authorization server для системы. Обслуживает два клиента: веб-фронт
(`authorization_code`+PKCE) и MCP-клиент (`mcp-gateway`, тот же флоу, свой
`client_id`/`redirect_uri`). Раздаёт JWKS для локальной верификации токенов
остальными сервисами. Несёт единственный в репозитории фронтенд-код —
минимальную login-форму.

**Чем не владеет:** доменными данными других сервисов, авторизационными
решениями внутри доменов (`deck` сам решает, может ли пользователь X
редактировать колоду Y, `authenticator` только подтверждает, кто такой X).

## Данные

- Схема БД: `auth`.
- Роли: `auth_migrator`, `auth_app`.
- Таблицы (ориентир, зависит от финальной реализации по ADR-0008):
  `users`, `oauth_clients`, `authorization_codes` (или делегировано Hydra,
  если выбор падёт на неё — тогда `auth` схема хранит только `users` и
  Hydra получает свою отдельную БД/схему).

## Контракты (не зависят от выбора реализации)

- `POST /oauth/authorize`, `POST /oauth/token` — стандартный
  `authorization_code`+PKCE, плюс `client_credentials` для сервис-к-сервису.
- `GET /.well-known/openid-configuration`
- `GET /.well-known/jwks.json`
- Claims в JWT: минимум `sub`, `exp`, `iat`, `scope`, `client_id`.
- Login-форма: `GET /login`, `POST /login` — простейший HTML, без SPA.

Полный флоу для MCP-клиента — [data-flows.md, сценарий 3](../../docs/arch/data-flows.md#3-sealeddraft-через-mcp-по-фото-карт).

## Паттерны здесь

- **Singleflight на выдачу JWKS** потребителям при истечении их локального
  кэша — не даёт шторма запросов при массовой ротации ключей у клиентов.
- Остальное определяется выбором по ADR-0008.

## Локальный запуск

До закрытия ADR-0008 — не применимо. Остальные сервисы на M0–M3 работают на
статическом dev-токене с фиксированным JWKS-заглушкой в `libs/authx`, не
дожидаясь этого сервиса.

## Метрики и алерты

RED-метрики на `/oauth/*`. Алерт на аномальный рост `invalid_grant`/провалов
токен-обмена (сигнал возможной атаки или сломанного клиента).

## Инварианты домена

- Приватные ключи подписи JWT никогда не покидают этот сервис — остальные
  сервисы работают только с публичной частью через JWKS.
- Ротация ключей — с grace period: старый `kid` валиден для верификации ещё
  некоторое время после появления нового, см. [security.md](../../docs/arch/security.md#jwks).
- `redirect_uri` строго matched по allowlist на клиента, никаких wildcard —
  типовая уязвимость OAuth2, которую easy проглядеть при самописной
  реализации.
