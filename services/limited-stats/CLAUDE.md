# CLAUDE.md — limited-stats

Гайд для Claude Code при работе внутри `services/limited-stats`. Общесистемный
контекст — в [docs/arch/](../../docs/arch/README.md), корневые правила — в
[корневом CLAUDE.md](../../CLAUDE.md).

Имя сервиса — по домену (limited-статистика), не по источнику: если завтра
добавится второй источник статистики помимо 17lands, он войдёт сюда же, а не
станет отдельным `17lands-parser`.

## Назначение и границы

Парсит и отдаёт статистику limited-форматов MTG (draft/sealed) с
17lands.com по расписанию. Настраиваемый список отслеживаемых выпусков.
Предоставляет REST для чтения статистики по картам.

**Чем не владеет:** карточными данными как таковыми (справочник — в `deck`,
этот сервис только ссылается на `card_id`/имя карты), статьями и инсайтами.

## Данные

- Схема БД: `limited_stats`.
- Роли: `limited_stats_migrator`, `limited_stats_app`.
- Таблицы: `tracked_sets` (конфиг — какие выпуски/форматы мониторить),
  `card_stats` (win rate, pick order и т.п. по `(set, format, card_name)`),
  `job_runs` (журнал прогонов для алертов и `job_last_success_timestamp`).
- Redis: cache-aside поверх `card_stats` для горячих запросов из
  `mcp-gateway`.

## Внешние зависимости

- **17lands.com** — нет официального публичного API с гарантиями, парсинг
  их страниц/экспортов по расписанию. Rate limit — консервативный
  token-bucket через `libs/httpx` (вежливость к ресурсу, у которого нет
  формального лимита). Честный User-Agent с контактом проекта — см.
  [security.md](../../docs/arch/security.md#парсеры-threat-заметки).
  При недоступности источника — прогон помечается failed, алерт летит,
  предыдущие данные не удаляются.

## Контракты

- REST + OpenAPI:
  - `GET /stats/cards?set=&format=` — статистика по картам выпуска.
  - `GET /tracked-sets`, `POST /tracked-sets`, `DELETE /tracked-sets/{id}` —
    управление конфигом мониторинга.
- gRPC: `StatsService.GetCardStats(set, format, cards[])` — для `mcp-gateway`.
- Kafka: не публикует и не потребляет на старте.

## Внутренняя раскладка (ориентир для M3)

```
internal/
  scheduler/   # распределённый шедулер, лизинг задач
  parser/      # разбор данных 17lands
  stats/       # хранение и выдача статистики
```

## Паттерны здесь

- **Распределённый шедулер с лизингом задач** (`SELECT ... FOR UPDATE SKIP
  LOCKED`, TTL аренды, heartbeat) — ключевой паттерн сервиса. Задача =
  `(set, format)` из `tracked_sets`. Несколько инстансов сервиса можно
  запустить параллельно, каждый берёт себе незанятые задачи.
- **Bounded worker pool** — ограниченный параллелизм парсинга, чтобы не
  утопить слабый сервер при большом количестве отслеживаемых выпусков.
- **Retry + backoff** — на HTTP-вызовы к 17lands.

Полное обоснование — [patterns.md](../../docs/arch/patterns.md).

## Локальный запуск

```
task up
go run ./cmd/migrate up
go run ./cmd/server
```

Для проверки лизинга — запустить `cmd/server` двумя процессами локально с
разными `INSTANCE_ID`, убедиться что задачи не дублируются.

## Метрики и алерты

Этот сервис — приоритетный по наблюдаемости с первого дня (фоновый процесс,
легко «тихо сломаться»):

- `job_runs_total{job,status}`, `job_duration_seconds{job}`,
  `job_last_success_timestamp{job}`, `scheduler_lease_holders{job}`.
- **Обязательные TG-алерты**: старт прогона, успешное завершение (с
  количеством обработанных карт), провал (с текстом ошибки), пропущенный
  шедул (прогон не начался в ожидаемое окно).

Подробности формата — [observability.md](../../docs/arch/observability.md).

## Инварианты домена

- Один `(set, format)` обрабатывается ровно одним инстансом в моменте —
  лизинг обязателен, не «best effort».
- Частичный/упавший прогон не должен затирать последние успешные данные —
  запись новых `card_stats` атомарна относительно записи `job_runs`.
- Конфиг `tracked_sets` меняется через REST, не через прямые правки в БД
  руками (иначе не увидим в аудите, что и когда включили/выключили).
